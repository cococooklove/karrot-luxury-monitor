# 매물 감시 탭 통합 — 설계

작성 2026-08-30. 대상 `delivery/integrated/manual_gui/`.
전제 문서: `2026-08-29-article-watchlist-design.md` (워치리스트 1단계, 구현 완료 `743325c`).

## 배경

지금 GUI 는 탭 세 개다. 수동 검색, 자동 모니터, 키워드 알림.

자동 모니터와 키워드 알림은 화면만 두 개인 게 아니라 **탐지 소스가 두 개**다.

| | 자동 모니터 | 키워드 알림 |
|---|---|---|
| 경로 | 검색 API 지역 스윕 | 앱 API 키워드 구독 후 폴링 |
| 조건 수 | 무제한 | 계정당 슬롯 상한 |
| 지연 | 스윕 한 바퀴 (수 분~수십 분) | 폴링 주기 (기본 120초) |
| 비용 | 지역×키워드만큼 요청 | 계정당 폴링 1회 |

클라가 실제로 원하는 것은 둘 중 하나가 아니라 하나의 결과다. "새 매물을 빨리 잡고,
잡은 매물을 계속 추적한다." 지금은 그 하나의 결과를 얻으려고 사용자가 두 탭을 오가며
서로 다른 설정을 맞춰야 하고, 같은 매물이 자동 모니터 표와 키워드 알림 표에 각각
따로 나타난다.

그래서 탭을 없애는 게 아니라 **소스 선택을 사용자에게서 걷어낸다**. 검색 스윕 엔진은
살리되 UI 에서 지우고, 키워드 슬롯이 모자랄 때 자동으로 동원되는 폴백으로 만든다.

## 범위

**하는 것**

- 탭 3개 → 2개 (수동 검색 / 매물 감시). 자동 모니터 탭 제거, 엔진 존치
- `KeywordRouter` — 키워드를 앱 API 슬롯 또는 검색 스윕으로 자동 배정
- `watch` 테이블을 매물 단일 진실로 확장, 가격 이력 테이블 추가
- 신규 매치 표 + 워치 이벤트 목록 → 매물 표 하나로 통합
- `SupervisorController` — 폴링·스윕·수확·크래시복구를 토글 하나가 관장
- 자동 모니터 탭의 스윕 설정 위젯을 고급 패널로 이관
- 기존 저장소(`auto_seen.db`, `match_seen.json`) 1회 백필

**하지 않는 것**

- 수동 검색 탭 변경
- 알림 채널 추가 (텔레그램·구글시트 그대로)
- 헤드리스 런타임의 CLI 인터페이스 변경 — 내부 배선만 새 컨트롤러를 쓴다

## 1. 화면

키워드 알림 탭을 **매물 감시**로 이름 바꾸고, 자동 모니터 탭을 지운다.

```
┌ 매물 감시 ───────────────────────────────────────────────────┐
│ [▶ 감시 시작]  토큰OK · 계정12 · 커버리지78% ·                │
│                다음폴링 2:31 · 추적중 143        [고급 ▾]     │
├──────────────────────────────────────────────────────────────┤
│ 키워드 [______] 가격 [___]~[___] 제외 [______] [추가] [일괄] │
│  ┌ 키워드 표 ────────────────────────────────────────────┐   │
│  │ 키워드 · 경로 · 매물수 · 신규24h · [삭제]              │   │
│  └───────────────────────────────────────────────────────┘   │
├──────────────────────────────────────────────────────────────┤
│ 필터: [전체][🆕신규][↓인하][✓종료]                            │
│  ┌ 매물 표 ──────────────────────────────────────────────┐   │
│  │ 상태 · 키워드 · 제목 · 지역 · 현재가 · Δ최초가 ·       │   │
│  │ 마지막변동 · 최초감지                                  │   │
│  └───────────────────────────────────────────────────────┘   │
├──────────────────────────────────────────────────────────────┤
│ ▸ 로그 (접힘)                                                 │
└──────────────────────────────────────────────────────────────┘
```

**컨트롤 바.** 버튼은 토글 하나다. 나머지는 읽기 전용 상태칩이고, 값이 없거나
비정상이면 색으로만 구분한다(정상 기본색, 경고 주황, 실패 빨강). 칩 클릭은 해당
고급 패널 항목으로 스크롤한다.

**키워드 표.** `경로` 열은 `앱` 또는 `스윕` 을 표시한다. 사용자가 고르는 값이 아니라
라우터가 정한 결과를 보여주는 진단용이다. 툴팁으로 사유("슬롯 만원, 스윕으로 폴백")를
붙인다.

**매물 표.** 매물 하나가 행 하나다. 신규로 잡히는 순간 행이 생기고, 같은 행이
갱신된다.

| 열 | 내용 |
|---|---|
| 상태 | 🆕 신규(24h 이내) / ● 추적중 / ↓ 인하 / ↑ 인상 / ✓ 종료 |
| 키워드 | 이 매물을 잡은 키워드 |
| 제목 | 매물명 |
| 지역 | 동네명 |
| 현재가 | 마지막 관측 가격 |
| Δ최초가 | 최초 감지가 대비 증감 (부호와 퍼센트) |
| 마지막변동 | 마지막 가격 변동 시각 (없으면 `-`) |
| 최초감지 | 워치리스트 진입 시각 |

행 더블클릭은 가격 이력 팝업을 연다: 시각·가격 목록과 매물 링크. 기존 더블클릭
동작(브라우저 열기)은 링크 버튼으로 옮긴다.

상태 필터는 배타 토글이다. 정렬은 열 헤더 클릭.

**고급 패널.** 접기 기본. 안에 들어가는 것:

- 폴링 간격, 커버리지 모드, 야간 감속
- 부팅 시 시작, 크래시 복구
- 알림 설정(텔레그램·구글시트), 계정, 프록시, 엑셀 내보내기
- **검색 스윕**: 지역 트리, 레인 수, 휴식 주기(min/max), 지역 간 갭(min/max),
  끌올 N일 이내

스윕 설정은 자동 모니터 탭에서 그대로 이사한다. 값 의미와 위젯 종류를 바꾸지 않는다.

## 2. 라우팅

새 모듈 `daangn_ext/keyword_router.py`.

```python
class KeywordRouter:
    def __init__(self, alerts: MultiAccountAlerts, sweep_queue: SweepQueue,
                 store: KeywordStore)
    def add(self, keyword: str, min_price=None, max_price=None,
            exclude=None) -> dict          # {"keyword":..., "route":"app"|"sweep", "reason":...}
    def remove(self, keyword: str) -> None
    def rebalance(self) -> list[dict]      # 슬롯이 빈 스윕 키워드를 앱으로 승격
    def routes(self) -> list[dict]         # 키워드 표용
```

**배정 규칙.**

1. `add` 는 먼저 앱 API 슬롯 여유를 본다. 여유 판단은 `MultiAccountAlerts` 가
   보고하는 계정별 등록 키워드 수와 슬롯 상한을 쓴다.
2. 여유가 있으면 `alerts.register_all(...)` 로 등록하고 `route="app"`.
3. 없으면 스윕 큐에 넣고 `route="sweep"`. 스윕 조건은 고급 패널의 지역·가격 설정을
   따른다.
4. 앱 등록이 밴 키워드(`is_banned`)로 거절되면 스윕으로 폴백하고 사유를 남긴다.

**슬롯 상한.** 하드코딩하지 않는다. 계정당 상한은 `data/config.json` 의
`keyword_slot_cap`(기본 30)으로 읽고, 실제 등록 수는 서버가 돌려주는
`KeywordAlertAPI.keywords()` 길이로 센다. 서버가 상한을 낮추면 등록 실패가 나므로,
실패 응답을 받으면 그 계정의 유효 상한을 관측값으로 낮춰 캐시한다.

**승격.** `rebalance` 는 감시 루프 틱마다 호출한다. 앱 슬롯이 비었고 스윕 큐에
키워드가 있으면 오래된 순으로 앱으로 올린다. 승격된 키워드는 스윕 큐에서 빠진다.
강등은 하지 않는다 — 앱 등록이 살아 있으면 유지한다.

`SweepQueue` 는 기존 자동 모니터 엔진(`AutoMonitor`)에 넘길 키워드 목록과 조건을
보관하는 얇은 저장소다. 엔진 자체는 손대지 않는다. 자동 모니터 탭이 만들던 cfg dict
는 그대로 만들되, `keyword`/`extra` 를 스윕 큐가 채운다.

## 3. 데이터 모델

기존 `data/watch.db` 를 확장한다. 새 DB 를 만들지 않는다.

**`watch` 테이블 추가 컬럼**

| 컬럼 | 뜻 |
|---|---|
| `keyword` TEXT | 이 매물을 잡은 키워드 |
| `source` TEXT | `app` / `sweep` — 최초 감지 경로 |
| `first_price` INTEGER | 최초 감지 시 가격 (Δ 계산용) |
| `last_change` INTEGER | 마지막 가격 변동 epoch, 없으면 NULL |

`state` 는 저장하지 않고 파생한다. `tier`, `status`, `first_seen`, `last_change` 로
계산한다.

| state | 조건 |
|---|---|
| `new` | `tier != dead` 이고 `now - first_seen < 24h` |
| `tracking` | `tier != dead` 이고 위가 아님 |
| `down` / `up` | `tracking` 이고 마지막 변동이 인하/인상, 변동 후 24h 이내 |
| `ended` | `tier == dead` |

파생으로 두는 이유는 중복 진실을 만들지 않기 위해서다. `tier` 와 `state` 를 둘 다
쓰면 한쪽만 갱신되는 버그가 난다.

**새 테이블 `price_history`**

```sql
CREATE TABLE IF NOT EXISTS price_history (
    article_id TEXT NOT NULL,
    ts INTEGER NOT NULL,
    price INTEGER NOT NULL,
    PRIMARY KEY (article_id, ts)
);
CREATE INDEX IF NOT EXISTS idx_price_hist ON price_history (article_id, ts DESC);
```

`WatchTracker.check_one` 이 `price_down` / `price_up` 이벤트를 만들 때 행 하나를
넣는다. 최초 등록 시에도 한 행 넣는다(그래야 Δ 기준선이 이력에 남는다).

**폐기.** `match_seen.json` 은 중복 알림 방지용으로만 쓰이는데 `watch` 테이블이
같은 역할을 한다(`dead` 행을 안 지우는 이유가 그것이다). 백필 후 제거한다.
`auto_seen.db` 도 같다.

**마이그레이션.** `WatchStore.__init__` 안에서 `ALTER TABLE ... ADD COLUMN` 을
컬럼별로 시도하고 `duplicate column name` 은 무시하는 방식으로 한다. 별도 마이그레이션
러너를 두지 않는다.

백필은 일회성 스크립트 `tools/backfill_listings.py` 로 분리한다. `auto_seen.db` 와
`match_seen.json` 에서 매물 id·제목·가격·최초 감지 시각을 읽어 `watch` 에 upsert 하고,
`tier` 는 `published_at` 기준으로 다시 판정한다. 이미 있는 행은 건드리지 않는다.

## 4. 추적 수명

1단계에서 정한 등급 체계를 그대로 쓴다. 변경하지 않는다.

| 등급 | 조건 | 점검 주기 |
|---|---|---|
| `fresh` | 게시 48시간 이내 | 4시간 |
| `aged` | 게시 2~14일 | 24시간 |
| `dead` | 판매완료·삭제·게시 14일 초과 | 점검 안 함 |

활성 상한 300건, 초과 시 `published_at` 오래된 순으로 강등. 계정당 일일 상한 300회.
연속 실패 5회면 `dead`.

추적 대상 결정은 자동이다. 매칭된 매물은 전부 `add_from_matches` 로 들어간다.
사용자가 고르지 않는다. 축출도 자동이다 — 판매완료·삭제는 `dead` 로 가서 스윕에서
빠지고, 게시 14일 초과도 `dead` 다.

스윕에는 검색 스윕이 새로 발견한 매물도 들어간다. `AutoMonitor` 결과를
`add_from_matches` 와 같은 형태로 정규화해서 같은 경로로 넣는다.

## 5. 알림

| 이벤트 | 알림 |
|---|---|
| 신규 발견 | 보냄 |
| `price_down` | 보냄 |
| `price_up` | 옵션 (고급 패널, 기본 꺼짐) |
| `republished` | 옵션 (기본 꺼짐) |
| `sold` / `deleted` | 안 보냄, 표에만 반영 |

채널과 문구 형식은 1단계 그대로다.

## 6. 수명주기

지금은 워치 타이머가 자동폴링 버튼에 묶여 있다(`main.py:1185-1194`). 자동폴링을 끄면
가격 추적도 멈춘다. 사용자 의도와 어긋난다.

`SupervisorController` 를 새로 둔다. GUI 위젯을 모르는 순수 클래스로 만들고, 신호로만
바깥과 통신한다.

```python
class SupervisorController(QtCore.QObject):
    status = QtCore.Signal(dict)       # 상태칩 갱신용
    matches = QtCore.Signal(list)      # 신규 매물
    events = QtCore.Signal(list)       # 가격 변동 등

    def start(self) -> None
    def stop(self) -> None
    def is_running(self) -> bool
```

`start` 가 켜는 것:

- 앱 API 폴링 타이머 (간격 = 고급 패널 값 × 야간 감속 배수)
- 워치 스윕 타이머 (10분 고정, 야간 감속 배수 적용)
- 검색 스윕 스레드 — 스윕 큐가 비어 있지 않을 때만
- `KeywordRouter.rebalance` — 폴링 틱에 얹는다

토큰 수확 스레드는 지금처럼 앱 시작과 함께 항상 돈다. 감시 토글과 무관하다 — 수확이
멈추면 다음 시작이 느려진다.

부팅 시 시작·크래시 복구는 `SupervisorController.start()` 를 부르는 것으로 통일한다.
지금 흩어져 있는 체크박스별 분기를 컨트롤러 안으로 모은다.

헤드리스 런타임(`_run_headless`)도 같은 컨트롤러를 쓴다. GUI 없이 `start()` 하고
신호를 로거에 연결한다.

## 7. 테스트

TDD. 네트워크를 타지 않는 단위 테스트가 기본이다.

**`KeywordRouter`**

- 슬롯 여유 → `route="app"`, `register_all` 호출됨
- 슬롯 만원 → `route="sweep"`, `register_all` 호출 안 됨
- 밴 키워드 → 스윕 폴백, 사유 기록
- `rebalance` — 슬롯이 비면 스윕 큐 최고참이 앱으로 승격, 큐에서 제거
- `rebalance` — 슬롯이 없으면 아무것도 안 함
- 등록 실패 응답 시 그 계정의 관측 상한이 낮춰지는지

**저장소**

- 새 컬럼이 붙은 기존 DB 를 열어도 깨지지 않는지 (마이그레이션 멱등성)
- `price_history` — 최초 등록 시 기준선 1행, 변동 시 1행 추가
- `state` 파생 — 6가지 조건 경계 각각 (24h 직전/직후, 변동 24h 직전/직후, dead)

**백필**

- `auto_seen.db` + `match_seen.json` fixture → `watch` 행 생성
- 이미 있는 행은 덮어쓰지 않음

**`SupervisorController`**

- `start` 가 폴링·스윕 타이머 둘 다 켜는지
- 스윕 큐가 비면 검색 스윕 스레드를 안 띄우는지
- `stop` 후 타이머가 전부 꺼지는지
- 야간 감속 배수가 두 타이머에 모두 곱해지는지

**GUI**

헤드리스 스모크 하나. 탭 2개가 뜨고, 토글이 컨트롤러 `start`/`stop` 을 부르고,
매물 표가 신호를 받아 행을 갱신하는지까지. 위젯 픽셀 검증은 하지 않는다.

## 8. 순서

1. `watch` 스키마 확장 + `price_history` + `state` 파생 (테스트 먼저)
2. 백필 스크립트
3. `KeywordRouter` + `SweepQueue`
4. `SupervisorController` — 기존 타이머 배선을 옮김, GUI 는 아직 그대로
5. 매물 표 위젯 — `matchTable` + `_watch_list` 를 대체
6. 고급 패널 — 스윕 설정 이관
