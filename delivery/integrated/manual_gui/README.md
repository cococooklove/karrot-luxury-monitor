## 알림 설정 (자동 모니터)

`자동 검색` 탭 → `알림 설정` 버튼.

| 항목 | 설명 |
|---|---|
| 텔레그램 토큰 | @BotFather 로 봇 생성 후 받은 `123456:AA...` |
| 텔레그램 방 | chat_id. 개인=양수, 그룹/채널=`-100...`. 봇에게 `/start` 또는 방 초대 먼저 |
| 구글시트 | 시트 URL (선택) |
| 시트 인증파일 | 구글 서비스계정 JSON 키. 시트를 그 계정 이메일과 **편집자**로 공유해야 함 |

- `테스트 발송` 으로 저장 전에 설정 검증 (실패 시 원인 표시 — 토큰오류/방오류/차단/권한).
- `저장` 하면 `notify.json`(권한 0600)에 기록 → 재시작해도 유지.
- 전송은 매물 여러 건을 한 메시지로 묶어 보냄(텔레그램 레이트리밋 회피).
  429 는 `retry_after` 만큼 대기 후 재전송, 실패는 로그에 반드시 표시.

테스트: `python notify_test.py`

## 차단(IP 스로틀) 대응 — 전부 자동, 설정할 것 없음

`settings.txt` 는 종전대로 1줄=요청 최소간격(ms), 2줄=동시요청 수, 3줄~=프록시다.
이 두 값은 **상한**이고, 실제 동작은 프로그램이 응답을 보고 스스로 조정한다.

| 상황 | 자동 동작 |
|---|---|
| 429(레이트리밋) | 그 IP 를 `Retry-After` 만큼(없으면 600초) 쉬게 하고 다른 IP 로 교체 |
| 403/401/451, 캡차 | 그 IP 1800초 쿨다운 + 교체 |
| 차단 신호 누적 | 요청 간격을 자동으로 늘림(x1.5씩, 최대 x8). 조용해지면 되돌림 |
| 프록시 수 < 동시요청 설정 | 동시요청을 프록시 수로 낮춤 (같은 IP 동시요청 = 차단 지름길) |
| 빈응답(0건) | 쿨다운 없이 즉시 다음 IP — 차단이 아니라 시점별 변동이다 |
| 5xx / HTML 구조변경 | IP 문제 아님 → 교체하지 않고 조기중단, 진단에 표시 |

**상태 확인**: 창 아래 상태바 우측에 상시 표시된다.

```
IP 19/20 (쿨다운 1, 540초 후 해제)  ·  간격 1500ms (자동감속 x1.5) · 최근 RATELIMIT 2회   [진단]
```

**`진단` 버튼**: 프록시를 IP 당 1회씩 찔러(20개 약 2초) 지금 상황을 판정한다 —
① 일부 IP 차단 ② 풀 전체 차단(업체 교체 필요) ③ 당근 전면차단·HTML 변경(IP 교체 무의미)
④ 정상. 진단으로 드러난 차단 IP 는 곧바로 쿨다운돼 다음 수집이 그 IP 를 피한다.

고급 조정이 필요하면 환경변수로만 연다(잘못 만지면 IP 를 태우는 값이라 UI 에는 없다):
`DAANGN_THROTTLE=off` (자동감속 끄기), `DAANGN_THROTTLE_MAX`, `_UP`, `_DOWN`, `_RECOVER`, `_CALM`.

테스트: `python throttle_test.py`
